# Reel Craft — website

A fully static, single-page marketing site built with **Next.js 16** (App Router, `output: "export"`), **React 19** and **GSAP**. `npm run build` writes plain HTML/CSS/JS/images to `out/`, which can be served by any web server (it is deployed to Hostinger; see [docs/DEPLOY.md](docs/DEPLOY.md)).

## Quick start

```bash
nvm use            # Node 22 (any Node >= 20.9 works)
npm install
npm run dev        # http://localhost:3000
```

| Command | What it does |
|---|---|
| `npm run dev` | Dev server (generates images first) |
| `npm run build` | Production build into `out/` |
| `npm run typecheck` / `npm run lint` | TypeScript and ESLint |
| `npm run preview` | Serve `out/` on http://localhost:3000 |
| `npm run images` | Regenerate optimised images from `assets-src/images/` |
| `npm run verify` | Check `out/` (SEO tags, budgets, no image metadata, …) |
| `npm run build:deploy` | Full release: checks, build, headers, verify, zip in `releases/` |
| `npm run test:e2e` | Playwright tests (mobile + desktop, accessibility, reduced motion) |

## Where things live

```
content/            ALL editable text: headings, labels, copy, prices, contact details, photo choices and alt text
                    (only a few screen-reader-only labels, e.g. the menu button, live in the components)
  site.ts           name, phone, e-mail, Instagram, nav links, site URL
  copy.ts           every section's headings and copy, FAQ, plans, add-ons, booking steps
  images.ts         which photo goes where + alt text, hero slides
assets-src/images/  ORIGINAL photos (never shipped; the build reads these)
app/                layout, page, metadata, robots/sitemap, global CSS
components/
  sections/         one server component per page section (+ HeroCarousel, FaqAccordion)
  nav/              header, MobileMenu
  ui/ media/        small shared pieces, <Picture>
  motion/           MotionController (the only place GSAP is started)
lib/motion/         scroll/entrance animations, one file per section
scripts/ deploy/    image pipeline, verification, release build, server config
```

## Editing content
Change text, phone, e-mail or Instagram handle in `content/` (`site.ts` for contact details, `copy.ts` for section text).

## Replacing photos
The images currently in the gallery and collage are **placeholders**.
1. Put the new file in `assets-src/images/` with the **same filename** (e.g. `pre3.jpg`), or add a new file and register it in `scripts/images.config.mjs`.
2. Run `npm run images` (also runs automatically before `dev` and `build`). It writes AVIF/WebP/JPEG sizes to `public/img/`, strips all metadata, and regenerates `lib/generated/images.ts`.
3. Update the alt text in `content/images.ts` (describe what is in the photo).

Two hero images are special:
- The round photo in the hero badge is `assets-src/images/avatar.jpg` (a placeholder for now). Replace it the same way (square, ~112 px is plenty).
- The gold glitter behind the hero is generated by `node scripts/make-glitter.mjs` (constants at the top control density and colour); run `npm run images` afterwards. To use your own texture, drop a `pattern-glitter.png` into `assets-src/images/` instead.

## Feed reels (videos)
The "From the Feed" cards are tap-to-play videos (Roka reels from the client's Google Drive folder). Nothing is downloaded until a card is tapped.
1. Put the masters in `assets-src/videos/` as `reel1.mp4`, `reel2.mp4`, ... (gitignored; the originals are large).
2. Run `swift scripts/encode-reels.swift` (macOS, no ffmpeg needed). It writes 720p H.264 files named `reelN.<hash>.mp4` to `public/video/` (committed), a poster frame `assets-src/images/reelN.jpg`, and `content/videos.generated.ts`.
3. Register a new poster in `scripts/images.config.mjs`, run `npm run images`, and add the reel with a screen-reader label to `feedReels` in `content/images.ts`.

`npm run verify` fails if a reel is over 10 MB or out/video is over 30 MB.

## Hero carousel
`heroSlides` in `content/images.ts` holds the hero photos. With **one** slide the two arrows are decorative (they keep the design's notches filled, are hidden from screen readers and do nothing). Add two or more photos (crop for a wide ~2.3:1 card) and they become working previous/next buttons.

## How motion works
- Sections are server-rendered, so the content is readable without JavaScript. Only motion, the mobile menu and opening FAQ answers need it (with JavaScript off, every FAQ answer is shown).
- Decorative loops (sparkles, marquee, the play-button ring, QR scan line) are **CSS animations**; off-screen ones are paused.
- Entrances and parallax are GSAP, started once by `components/motion/MotionController.tsx` from `lib/motion/`. Each section opts in with `data-motion-root="<id>"`.
- Everything is gated behind `prefers-reduced-motion: no-preference`. With reduced motion the page is static and the gallery is a normal swipeable strip.
- On screens >= 900px the gallery pins and scrolls sideways; below that it is a native scroll-snap strip.

## Conventions
- No `next/image` (static export has no image server): use `components/media/Picture`.
- HTTP headers cannot be set in `next.config.ts` under `output: "export"`; they live in `deploy/` and are written to `out/.htaccess` by `npm run build:deploy`.
- Set `NEXT_PUBLIC_SITE_URL=https://your-domain` when building for production (canonical URLs, Open Graph, sitemap and JSON-LD use it).
